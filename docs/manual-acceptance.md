# 課堂搶答系統人工驗收清單

## 驗收準備

- [ ] 執行 `npm ci`、`npx playwright install chromium`、`npm run dev`。
- [ ] 健康檢查回傳 `status: ok`。
- [ ] 開啟一個老師瀏覽器 context，以及第一組、第二組兩個互相隔離的學生 context。
- [ ] 使用 `tests/fixtures/guided-notes/reference-single-template.xlsx`；不得使用真實學生資料。

## 老師匯入與建立活動

1. 老師上傳 XLSX。
   - 預期：顯示 6 題、各題題號、工作表、動態答案範圍及原內容警告。
   - 通過：沒有固定儲存格假設，也沒有在確認前建立活動。
2. 老師按「確認並建立活動」，記下畫面顯示的活動識別碼。
   - 預期：出現 `DRAFT` 活動、活動識別碼與組別管理。
3. 建立「第一組」及「第二組」。
   - 預期：兩組均出現在老師畫面；重複或空白名稱被拒絕。
4. 老師按「開始搶答」。
   - 預期：活動變成 `OPEN`，所有題目同時開放，組別不能再修改。

## 多組學生與隱私

5. 兩個學生 context 輸入同一 `activityId`，分別選擇第一組、第二組。
   - 預期：各自建立 HttpOnly session 並看到全部題號。
6. 兩組近乎同時提交第一題；再分別提交第二、第三題。
   - 預期：老師即時看到兩組名稱、答案及時間；學生只看到自己組別資料。
7. 第二組修改第一題答案並確認。
   - 預期：老師看到新答案與新時間；舊歷程保留但不再是有效答案。
8. 另開學生 context 再選第一組，修改第一組第二題。
   - 預期：原第一組畫面經 socket 通知或重連 snapshot 顯示同組最新答案。
9. 在學生 Network 檢查 `snapshot`。
   - 通過：不含其他組答案、提交狀態、時間、`receiveSequence` 或暫時順位。
10. 嘗試以第一場學生 session 查詢另一活動 snapshot。
    - 通過：伺服器回覆 403，URL、query 或 body 竄改不能改變 session 綁定組別。

## 重連、冪等與截止

11. 將第一組 context 暫時離線，由同組另一 session 修改答案，再恢復連線。
    - 預期：重連後重新抓 HTTP snapshot，顯示最新答案；不依賴事件重播。
12. 對同一題用相同 idempotency key 與相同答案重送兩次。
    - 通過：兩次回應相同，沒有新增有效提交、接收序號或 revision。
13. 老師按「結束活動」並接受確認，請求期間再次嘗試點擊。
    - 預期：按鈕顯示「結束中…」且停用，只送出一個 close；成功後切換唯讀結果。
14. 截止後送出延遲提交或修改 API。
    - 通過：伺服器回覆 409，資料與結果不變。

## 結果與匯出

15. 老師查看結果。
    - 預期：每題顯示成功組別及所有組別的順位、答案、伺服器時間；沒有判分或遞補操作。
16. 兩組學生查看結果。
    - 預期：只顯示各題成功組別名稱／識別碼，以及本組答案與順位；成功組別不是自己時，也看不到其答案、時間或順位欄位。
17. 老師按「下載已回填 Guided Notes」。
    - 預期：瀏覽器下載新的 `.xlsx`，來源檔沒有被覆蓋。
18. 比較來源與匯出檔。
    - 通過：第一名最後有效答案寫入動態 answer anchor；無成功組別保留原值；所有工作表及順序、非目標值／公式、格式、合併範圍、列高、欄寬、工作表／列／欄隱藏狀態完全一致。

## 實際走查紀錄

2026-10-25 以 Playwright 1.64.1 的真實 Chromium，使用一個老師、兩個不同組學生及一個同組第二 session context 完整執行上述流程。包含真實 SQLite、HTTP、Socket.IO 與瀏覽器下載；下載檔再由 ExcelJS 與來源 fixture 完整語意比較，結果通過。執行命令與結果摘要見 [Change review 驗證紀錄](change-review.md)。
