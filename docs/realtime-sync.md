# 即時同步與恢復範圍

Socket.IO 僅負責通知畫面「已有較新的伺服器狀態」，HTTP API 與 SQLite 才是活動、答案及截止結果的權威來源。

## 連線與資料範圍

- 連線 handshake 使用與 HTTP 相同的 HttpOnly session cookie，並指定目標活動。
- 老師只加入該活動的 teacher room；學生只加入 session 所綁定活動與組別的 group room。
- 老師提交事件包含題目、組別、最新答案、時間與 revision；學生事件只包含自己組別的題目、答案、時間與 revision。
- 活動截止事件不攜帶答案、順位或完整結果。

## Revision 規則

用戶端只套用 revision 大於目前快照的允許事件。revision 是狀態新舊水位，不是每個學生都會連續收到的訊息編號；學生遇到跳號時會直接套用較新事件，不會據此推論其他組別是否提交，也不會只因跳號要求事件重播。

## 斷線重連

初次載入及 socket 每次重新連線後，用戶端都重新呼叫符合目前角色權限的 HTTP snapshot，並以回傳內容完整取代畫面中的可見狀態。恢復範圍只包含 snapshot 提供的活動階段、題目與該角色可見的最新提交；系統不重播斷線期間的逐筆事件，也不恢復學生無權查看的資料。

若重連後 snapshot 暫時失敗，畫面會標示「尚未同步」、停用寫入並提供重試。持續連線期間若單一通知遺失，系統不承諾只靠 revision 跳號自動偵測；使用者可重新整理以取得最新權威 snapshot。
