# Spec Delta

## MODIFIED Requirements

### Requirement: 老師查看完整結果
活動結束後，系統 SHALL 允許老師依題號及完整題目文字查看每題所有有效組別的完整順位、最後有效答案及最後有效提交時間，並明確標示成功組別。

#### Scenario: 老師查看已結束活動
- **WHEN** 老師開啟 `CLOSED` 活動的結果頁
- **THEN** 系統依題號與完整題目文字顯示成功組別及所有有提交組別的順位、答案與最後有效提交時間

#### Scenario: 老師重新進入已結束活動
- **WHEN** 老師重新整理或重新選擇既有 `CLOSED` 活動
- **THEN** 系統顯示與首次關閉後相同的題目文字、成功組別、順位與匯出操作

#### Scenario: 老師檢查答案
- **WHEN** 老師閱讀任一結果答案
- **THEN** 系統僅提供檢視，不提供正誤標記、取消成功或遞補操作

### Requirement: 學生查看受限結果
活動結束後，系統 SHALL 向學生顯示每題題號、完整題目文字、成功組別的名稱或識別碼，以及自己組別在有提交題目中的最後有效答案與順位。除 session 所綁定的自己組別外，系統 MUST 不向學生公開任何其他組別的答案、提交時間或順位；此限制同樣適用於成功組別。

#### Scenario: 學生組別有提交
- **WHEN** 學生查看 `CLOSED` 活動且自己組別對某題有有效提交
- **THEN** 系統顯示該題題號、完整題目文字、成功組別，以及自己組別的答案與順位

#### Scenario: 學生組別沒有提交
- **WHEN** 學生查看 `CLOSED` 活動且自己組別未對某題提交
- **THEN** 系統顯示該題題號、完整題目文字、成功組別名稱或識別碼與自己組別未作答狀態，不顯示其他組答案、提交時間或順位

#### Scenario: 自己組別是成功組別
- **WHEN** 學生所在組別取得某題第一名
- **THEN** 系統同時將該組顯示為成功組別，並顯示自己的答案與第一名順位

#### Scenario: 嘗試查詢其他組完整結果
- **WHEN** 學生竄改請求以取得其他組別答案或順位
- **THEN** 系統拒絕請求或移除受限制欄位，且不得洩漏其他組完整資料

#### Scenario: 其他組是成功組別
- **WHEN** 學生查看某題結果且成功組別不是自己組別
- **THEN** 系統只顯示該成功組別的名稱或識別碼，不回傳或顯示其答案、提交時間或順位欄位
