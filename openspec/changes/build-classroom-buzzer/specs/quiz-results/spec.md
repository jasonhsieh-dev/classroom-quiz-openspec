# Spec Delta

## Purpose

定義活動結束後結果的建立、穩定性與依角色公開範圍，使老師可完整檢查答案，同時避免向學生公開其他組別的完整作答內容。

## ADDED Requirements

### Requirement: 截止後建立最終結果
系統 SHALL 在活動成功轉為 `CLOSED` 後，依每題的最終有效提交集合建立穩定順位及成功組別。重複讀取或重複結束請求 MUST 不改變既有結果。

#### Scenario: 題目具有多組提交
- **WHEN** 活動結束且某題具有一個以上有效提交
- **THEN** 系統保存該題完整順位，並將第一名保存為成功組別

#### Scenario: 題目無人提交
- **WHEN** 活動結束且某題沒有有效提交
- **THEN** 系統將該題標示為無成功組別且不產生虛構順位

#### Scenario: 重複讀取結果
- **WHEN** 活動關閉後多次讀取相同結果
- **THEN** 系統回傳相同成功組別、順位、答案及提交時間

### Requirement: 老師查看完整結果
活動結束後，系統 SHALL 允許老師查看每題所有有效組別的完整順位、最後有效答案及最後有效提交時間，並明確標示成功組別。

#### Scenario: 老師查看已結束活動
- **WHEN** 老師開啟 `CLOSED` 活動的結果頁
- **THEN** 系統依題號顯示成功組別及所有有提交組別的順位、答案與最後有效提交時間

#### Scenario: 老師檢查答案
- **WHEN** 老師閱讀任一結果答案
- **THEN** 系統僅提供檢視，不提供正誤標記、取消成功或遞補操作

### Requirement: 學生查看受限結果
活動結束後，系統 SHALL 向學生顯示每題成功組別的名稱或識別碼，以及自己組別在有提交題目中的最後有效答案與順位。除 session 所綁定的自己組別外，系統 MUST 不向學生公開任何其他組別的答案、提交時間或順位；此限制同樣適用於成功組別。

#### Scenario: 學生組別有提交
- **WHEN** 學生查看 `CLOSED` 活動且自己組別對某題有有效提交
- **THEN** 系統顯示該題成功組別，以及自己組別的答案與順位

#### Scenario: 學生組別沒有提交
- **WHEN** 學生查看 `CLOSED` 活動且自己組別未對某題提交
- **THEN** 系統只顯示該題成功組別的名稱或識別碼與自己組別未作答狀態，不顯示其他組答案、提交時間或順位

#### Scenario: 自己組別是成功組別
- **WHEN** 學生所在組別取得某題第一名
- **THEN** 系統同時將該組顯示為成功組別，並顯示自己的答案與第一名順位

#### Scenario: 嘗試查詢其他組完整結果
- **WHEN** 學生竄改請求以取得其他組別答案或順位
- **THEN** 系統拒絕請求或移除受限制欄位，且不得洩漏其他組完整資料

#### Scenario: 其他組是成功組別
- **WHEN** 學生查看某題結果且成功組別不是自己組別
- **THEN** 系統只顯示該成功組別的名稱或識別碼，不回傳或顯示其答案、提交時間或順位欄位

### Requirement: 開放期間不公布學生順位
活動為 `DRAFT` 或 `OPEN` 時，系統 MUST 不向學生提供其他組提交狀況、暫時成功組別或任何順位。學生 SHALL 只能看到自己組別目前的答案與提交狀態。

#### Scenario: 學生在活動進行中查看狀態
- **WHEN** 學生於 `OPEN` 活動查詢題目狀態
- **THEN** 系統只顯示本組各題未作答或已提交狀態、本組答案及最後有效提交時間

### Requirement: 人工檢查不改變結果
老師人工檢查答案 MUST 不改變成功組別、順位或 Guided Notes 匯出答案來源。系統 MUST 不建立自動判分或人工正誤欄位。

#### Scenario: 老師認為成功答案錯誤
- **WHEN** 老師人工檢查後認為成功組別答案不正確
- **THEN** 系統仍維持該組為成功組別，且匯出仍使用該組最後有效答案
