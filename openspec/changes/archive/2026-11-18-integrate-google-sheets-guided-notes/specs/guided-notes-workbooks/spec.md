## MODIFIED Requirements

### Requirement: 動態辨識表頭與題目
系統 MUST 掃描工作表以尋找同一表頭列中的「題號」、「題目」與「作答」，忽略合併範圍中的非主儲存格，並以題號欄下方的非空值建立題目。系統 MUST 允許工作表、列、欄位置、合併範圍及題目數量變動，且 MUST 不依賴範例檔的固定儲存格位置或固定間隔列。

#### Scenario: 題目位置與數量改變
- **WHEN** 有效學習單將三個表頭及題目移至不同列或欄，並具有與範例不同的題目數量
- **THEN** 系統依實際表頭、題號值與題目文字建立完全相同數量的題目

#### Scenario: 題目之間包含空白列
- **WHEN** 題號欄在有效題目之間具有空白或格式化分隔列
- **THEN** 系統略過空白列，且不將它們建立為題目

#### Scenario: 題目表頭與內容使用合併儲存格
- **WHEN** 「題目」表頭或某題完整文字位於水平或跨列合併範圍
- **THEN** 系統只將該合併範圍視為一個欄位，並由其主儲存格取得完整可見文字

#### Scenario: 跨列題目對應單一題號
- **WHEN** 一個題號列的題目範圍延伸至後續沒有題號的列
- **THEN** 系統將合併範圍的完整文字關聯到該題號，且不為延伸列建立額外題目

#### Scenario: 找不到唯一表頭
- **WHEN** 所選分頁缺少「題號」、「題目」或「作答」任一必要表頭，或存在多組候選而無法唯一辨識目標工作表與表頭列
- **THEN** 系統拒絕匯入並指出缺漏或歧義原因

#### Scenario: 題目文字缺漏或無法唯一定位
- **WHEN** 任一有效題號沒有非空題目文字，或同列存在多個無法唯一決定的題目來源
- **THEN** 系統拒絕整次匯入並指出受影響的題號、工作表或列

### Requirement: 建立答案儲存格 mapping
系統 SHALL 將每一題映射到同列且涵蓋「作答」欄的普通儲存格或合併範圍，並保存工作表名稱、題號儲存格、完整答案範圍、答案範圍左上角及原始值。合併範圍的實際寫入目標 MUST 為左上角儲存格。

#### Scenario: 映射合併答案範圍
- **WHEN** 題目同列的作答位置是涵蓋作答欄的合併範圍
- **THEN** 系統在預覽中顯示完整範圍，並將其左上角記錄為寫回寫入目標

#### Scenario: 題目缺少答案位置
- **WHEN** 任一題無法找到唯一且有效的答案儲存格或合併範圍
- **THEN** 系統拒絕整次匯入，且指出受影響的題號或列

#### Scenario: 答案範圍互相重疊
- **WHEN** 兩個題目被解析到相同或互相重疊的答案範圍
- **THEN** 系統拒絕整次匯入，避免寫回時答案互相覆蓋

### Requirement: 驗證題號
系統 MUST 將顯示題號保存為字串，並 MUST 要求同一活動內正規化後的題號唯一。沒有任何題目或具有重複題號的所選分頁 MUST 被拒絕。

#### Scenario: 使用文字型題號
- **WHEN** 學習單題號為 `1-1`、`A1` 或其他非空文字
- **THEN** 系統保留其顯示內容並將其作為可選擇題號

#### Scenario: 出現重複題號
- **WHEN** 解析結果包含兩個正規化後相同的題號
- **THEN** 系統拒絕匯入並列出重複題號

#### Scenario: 學習單沒有題目
- **WHEN** 找到表頭但題號欄下方沒有任何有效題號
- **THEN** 系統拒絕匯入並說明沒有可建立的題目

### Requirement: 提供匯入預覽與確認
系統 SHALL 在建立活動前顯示解析出的題目數、每題顯示題號、完整題目文字、工作表及答案範圍。若答案目標原本具有非空內容，系統 MUST 對該題顯示覆蓋警告；老師確認後系統才可保存雲端來源、題目快照與 mapping。

#### Scenario: 預覽空白答案格
- **WHEN** 解析成功且答案目標為空白
- **THEN** 預覽顯示題號、完整題目文字與目標範圍，且不顯示原內容覆蓋警告

#### Scenario: 預覽既有答案內容
- **WHEN** 任一答案目標已具有內容
- **THEN** 預覽標示該題將在有成功組別時覆蓋原內容，並要求老師確認後才建立活動

#### Scenario: 老師取消匯入
- **WHEN** 老師在預覽階段取消
- **THEN** 系統不建立活動、不保存題目文字或 mapping，且不產生寫回檔

### Requirement: 保存完整題目文字而不改變答案 mapping
系統 SHALL 為每題保存完整題目文字及必要的來源定位資料，並 MUST 將題目文字視為顯示資料，不得用它取代或改變題號、工作表、題號儲存格、答案範圍、答案 anchor、原始答案或題目排序。`receive_sequence`、順位與寫回答案來源 MUST 不受題目文字影響。

#### Scenario: 確認包含完整題目的匯入
- **WHEN** 老師確認具有有效題號、題目文字及答案 mapping 的匯入預覽
- **THEN** 系統將題目文字與原有 mapping 一併保存，且原有 mapping 欄位保持解析結果不變

#### Scenario: 題目文字包含換行或格式化文字
- **WHEN** 題目儲存格包含可顯示的換行、富文字或公式結果
- **THEN** 系統保存 Google Sheets 可見的完整文字內容，且不將版面格式或公式本身加入學生可編輯資料

#### Scenario: 匯出包含題目文字的活動
- **WHEN** 老師寫回已結束且保存完整題目文字的活動
- **THEN** 系統仍只修改成功題目的答案 anchor 值，題目文字儲存格及所有其他未指定內容保持不變

## ADDED Requirements

### Requirement: 直接讀取 Google Sheets
系統 SHALL 使用 Google Sheets API v4 與後端 Service Account，接受有效 Google Sheets 網址，列出分頁並由老師選擇單一分頁產生預覽。新活動 MUST 不接受 XLSX 上傳或以下載 XLSX 代替 API 讀取。

#### Scenario: 選擇雲端分頁
- **WHEN** 老師提供可存取的試算表網址並選擇分頁
- **THEN** 系統從雲端讀取儲存格與合併範圍，僅解析所選分頁；其他分頁候選不造成歧義

#### Scenario: 拒絕不安全網址
- **WHEN** 網址不是允許的 Google Sheets 文件格式
- **THEN** 系統拒絕輸入且不對該網址發出 HTTP 請求

#### Scenario: 混合題目版面
- **WHEN** 所選分頁混合單題與題組區塊，具有唯一表頭與唯一題號
- **THEN** 系統依實際題號及位置建立題目，不新增題組管理；缺漏文字、重複題號或重疊範圍仍拒絕

#### Scenario: 空白答案格
- **WHEN** API 省略有效作答欄內的空白格資料
- **THEN** 系統依網格座標及合併範圍辨識空白格，不因省略資料而判為缺少答案位置

### Requirement: 保存雲端來源與歷史相容
系統 MUST 保存來源種類、spreadsheetId、sheetId、題目快照、mapping、結構指紋及目標原始輸入值。確認匯入前 MUST 重讀並檢查預覽一致性。版本化遷移 MUST 保留舊活動、提交、結果及 XLSX，不得使用假的本機路徑代表雲端來源。

#### Scenario: 預覽後文件改變
- **WHEN** 確認前題目內容、結構或目標原值已變更
- **THEN** 系統拒絕建立活動並要求重新預覽

#### Scenario: 保留歷史
- **WHEN** 既有資料庫升級並重啟
- **THEN** 舊活動與來源檔仍可讀取及恢復；不自動綁定或寫入雲端文件

### Requirement: 精確寫回雲端答案
系統 SHALL 僅於 CLOSED 且老師確認目標與答案預覽後，使用單次 batchUpdate 寫入原綁定試算表與分頁的第一名答案 anchor。答案 MUST 為字串；未作答格及非目標值、公式、格式、合併範圍與版面 MUST 不修改。寫回前 MUST 比較結構、題目來源及目標原值，寫回後 MUST 重新讀取核對。

#### Scenario: 寫回成功答案
- **WHEN** 老師確認 CLOSED 活動的寫回預覽
- **THEN** 系統只寫入具有成功組別的答案，等號開頭仍為文字，並於核對成功後報告成功

#### Scenario: 來源衝突
- **WHEN** 寫回前來源結構、題目內容或目標原值不同於確認基準
- **THEN** 系統停止寫回並提示衝突，不自動改綁或覆蓋

#### Scenario: 錯誤狀態
- **WHEN** 活動尚為 DRAFT 或 OPEN
- **THEN** 系統拒絕寫回且不呼叫更新 API

#### Scenario: 非目標保護
- **WHEN** 批次更新包含多個合併答案 anchor
- **THEN** 系統僅改變目標輸入值，其他分頁與非目標內容及格式保持不變；核對差異不得報告成功

### Requirement: 可靠寫回操作
系統 MUST 保存操作識別、結果版本、狀態及去敏錯誤。重複操作 MUST 不產生不同寫入；結果不明 MUST 先讀取核對，不盲目重送或自動覆原。Google 操作與 SQLite 不宣稱跨系統原子性。

#### Scenario: 重複成功操作
- **WHEN** 相同結果版本已確認成功後再次要求寫回
- **THEN** 系統回傳既有成功狀態而不重新覆蓋目標

#### Scenario: 回應遺失
- **WHEN** 請求逾時或服務在寫入後重啟
- **THEN** 系統標示結果不明並核對；全部目標符合則成功，全部仍為原值且結構一致才允許重試，混合或其他值則停止並提示人工處理

#### Scenario: 批次無效
- **WHEN** 任一目標不可寫入使整批請求被 Google 拒絕
- **THEN** 系統報告失敗，保留結果，不拆批繼續寫入

#### Scenario: 沒有成功答案
- **WHEN** CLOSED 活動沒有任何成功組別
- **THEN** 系統顯示無需寫回且不發出更新請求

### Requirement: 保護雲端授權與錯誤邊界
憑證 MUST 僅由後端讀取，不得出現在前端、Git、README 範例實值、學生資料或日誌。雲端讀寫 MUST 要求既有老師 Session 與本機請求保護。系統 SHALL 區分可辨識的授權、文件不存在、連線及配額錯誤，不洩漏敏感資訊。

#### Scenario: 失去權限或 API 錯誤
- **WHEN** Google 回傳授權失效、403、404、429 或連線失敗
- **THEN** 系統顯示對應繁體中文處理提示；無法判別無權限與不存在時明示文件不存在或無權存取，不捏造原因；配額重試有上限

#### Scenario: 學生嘗試寫回
- **WHEN** 學生或無有效老師 Session 呼叫雲端操作
- **THEN** 系統拒絕且不呼叫 Google API


### Requirement: 後端單次更新模式
系統 SHALL 允許可信後端設定啟用單次更新模式。單次模式 MUST 在更新前持久記錄已嘗試，且同一操作識別最多發出一次 batchUpdate，不得由服務、授權重播或 HTTP 重試再次更新；讀回核對仍可執行。再次更新 MUST 重新讀取與檢查、明確建立新操作並再次確認，保留舊操作紀錄。前端 MUST 不得任意指定內部重試參數。

系統 MUST 在 SQLite 保存每次取得或接手之操作權識別；所有跨 await 的流程在外部更新前 MUST 以原子條件更新核對有效操作權、狀態、租期及未嘗試標記，並檢查受影響列數。只有成功取得資格者可呼叫 Writer。單次已嘗試標記 MUST 不可被舊快照或租期接手清除；過期操作權 MUST 不得覆寫新狀態、錯誤或成功結果。

#### Scenario: 單次模式遇到錯誤或重複確認
- **WHEN** 單次操作遇到 429、5xx、逾時、回應遺失、並行或重複確認
- **THEN** 同一操作最多更新一次，結果不明先核對，不因重啟或切換設定再更新

#### Scenario: 租期接手後舊讀取恢復
- **WHEN** A 的讀取尚未完成而租期過期，B 接手、核對並成功更新後 A 才恢復或回報錯誤
- **THEN** A 不取得寫入資格、不呼叫 Writer，也不覆寫 B 的 SUCCEEDED 或錯誤紀錄；同一操作僅更新一次

#### Scenario: 已取得單次資格後過期
- **WHEN** A 已持久取得單次更新資格而租期過期，另一請求或重啟後的服務接手
- **THEN** 同一 operationId 不再核發更新資格，接手只可讀回核對；舊請求不得覆寫接手後的狀態，必要的新更新須另經明確 renew 與新的 operationId

#### Scenario: 明確重新建立操作
- **WHEN** 已嘗試的單次操作確定 FAILED，老師明確要求新操作
- **THEN** 系統重新檢查來源與原值，保存舊操作歷史，產生新識別與預覽，等待另一次明確確認；UNKNOWN、CONFLICT 或成功狀態不得直接重新更新

### Requirement: 老師查詢有效寫回模式
系統 SHALL 提供受既有老師權限及本機安全邊界保護的唯讀查詢，回傳實際處理寫回的服務實例之有效單次更新模式與不含機敏資訊的實例識別。寫回狀態 SHALL 使用相同實例識別。查詢 MUST 不接受前端覆寫模式，不呼叫 Google 或改變操作紀錄，亦不得改變公開 health 回應。

#### Scenario: 有效模式與服務實例一致
- **WHEN** 老師查詢有效模式與同一後端的寫回狀態
- **THEN** 系統回傳實際模式布林值及一致實例識別；啟用為 true，一般模式為 false，不包含其他設定或憑證

#### Scenario: 非老師查詢
- **WHEN** 查詢沒有有效老師 Session 或只有學生 Session
- **THEN** 系統拒絕查詢，不洩漏模式或內部資料
