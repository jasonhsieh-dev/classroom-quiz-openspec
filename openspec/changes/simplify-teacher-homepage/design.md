# Design

## Context

動機見 proposal.md。`TeacherApp` 的 `loadRoot` 目前讀取活動摘要、恢復唯一 OPEN 並改寫 URL；沒有 OPEN 才顯示匯入與歷史清單。指定活動網址則透過獨立的 `loadActivity` 取得權威 snapshot。兩條路徑均先初始化老師 Session，可在前端分開調整。

## Goals / Non-Goals

**Goals:** 保持首頁為匯入入口，以最少導覽元素保留 OPEN 可發現性，沿用活動頁與既有錯誤重試流程。

**Non-Goals:** 不增加活動管理頁、歷史搜尋或即時首頁監看；不變更 proposal.md 所列的任何後端、資料與核心規則。

## Decisions

1. **沿用摘要 API，只取 OPEN 作為提示資料。** Session 成功後仍呼叫 `GET /api/teacher/activities` 並驗證回應，首頁僅保存／使用 OPEN 摘要，不渲染 DRAFT／CLOSED。移除 `loadRoot` 的 snapshot 呼叫與自動 `replaceState`，並清除目前活動與恢復錯誤狀態。相較新增 OPEN 專用 API，此方案符合不改後端的限制；相較完全不查詢摘要，可提供必要返回入口。
2. **使用真正的活動網址連結。** 提示可用「目前有進行中的活動；開始另一場前，請先返回並結束該活動。」搭配「返回進行中活動」，href 為編碼後的 `/teacher/activities/:activityId`。透過正常頁面導覽沿用 Session 初始化與 snapshot，避免另建恢復流程；不把提示做成自動導向或完整歷史列表。
3. **維持既有匯入與錯誤邊界。** 有／沒有 OPEN 均保留匯入操作，匯入確認後仍進入新 DRAFT 的活動網址。Session 失敗仍停用匯入並可重試；摘要失敗或格式無效仍顯示錯誤與重試，不當作空清單。指定活動恢復失敗的「返回活動清單」改為「返回匯入首頁」，回到 `/` 後載入首頁摘要但不恢復 OPEN。無需引入路由套件或重寫瀏覽器歷史管理。
4. **以既有測試擴充驗證。** `App.test.tsx` 改寫兩個舊首頁測試，涵蓋空資料、僅歷史、有 OPEN 混合歷史、正確連結、URL 不變、未請求 snapshot、Session／摘要失敗與重試、錯誤後返回首頁；保留三種直接網址恢復與匯入相關測試。E2E 在現有完整流程中增加有 OPEN 時另頁進入／重新整理 `/`、確認匯入與提示、點連結恢復同一活動；CLOSED 後再開首頁確認沒有提示與歷史清單。保留 DRAFT／OPEN／CLOSED 重新整理、同 profile Session、多人提交、排名、截止與 XLSX 匯出的完整回歸。

## Risks / Trade-offs

- [舊 OPEN 仍阻擋新活動開始] → 保留既有單一 OPEN 規則，提示與返回連結讓老師自行回去結束，不自動 close。
- [摘要提示在其他頁面結束活動後可能過時] → 首頁重新整理或重新進入時重讀摘要；點連結後以 snapshot 顯示實際狀態，不新增 Socket.IO 訂閱或輪詢。
- [歷史活動不再能從首頁選擇] → README 與人工驗收說明保存活動網址；SQLite 與直接網址恢復保持原樣。
- [測試仍預期舊自動恢復或返回清單文案] → 更新首頁與錯誤返回斷言，保留 Session、snapshot、匯入匯出的既有回歸。

## Migration Plan

實作時只更新前端、測試與操作文件，無資料遷移或清理。更新人工驗收的現行步驟並新增本輪結果，不改寫前兩輪歷史驗收紀錄。若需回復，還原本輪前端與文件即可，資料庫與活動狀態不受影響。
