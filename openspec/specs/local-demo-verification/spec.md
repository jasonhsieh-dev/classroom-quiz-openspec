# local-demo-verification Specification

## Purpose

定義期末專題可在單機環境重現、測試與人工驗收的最低交付標準，包含自動化測試、合成資料及老師與至少兩組學生的並行 Demo。

## Requirements

### Requirement: 提供可重現的本機啟動流程
專案 MUST 提供繁體中文本機啟動說明，列出必要工具版本、安裝、環境設定、資料庫初始化、啟動前後端及停止服務的步驟。使用者 SHALL 不需要公開部署或雲端帳號即可完成核心 Demo。

#### Scenario: 全新環境依文件啟動
- **WHEN** 驗收者在符合版本要求的本機環境依 README 執行步驟
- **THEN** 系統啟動老師端、學生端、後端與本機資料庫，且可完成健康檢查

#### Scenario: 缺少必要設定
- **WHEN** 啟動時缺少必要環境變數或資料目錄無法使用
- **THEN** 系統以不洩漏機密的訊息指出缺少項目，且不以不明錯誤繼續執行

### Requirement: 提供自動化測試入口
專案 MUST 提供單一文件化指令執行核心自動化測試，並 SHALL 讓測試失敗時回傳非零結束狀態。測試 MUST 可使用隔離的暫存資料庫與合成檔案，不依賴真實課堂資料。

#### Scenario: 執行完整自動化測試
- **WHEN** 開發者執行文件指定的完整測試指令
- **THEN** 系統執行單元、API 整合與瀏覽器端對端測試，並輸出各測試層結果

#### Scenario: 測試案例失敗
- **WHEN** 任一必要測試未通過
- **THEN** 測試指令回傳非零狀態並指出失敗案例

### Requirement: 核心規則具有自動化驗證
自動化測試 MUST 涵蓋動態匯入、組別 session 隔離、每題依單調接收序號獨立排名、修改重設有效接收資訊、冪等相同／衝突 payload、並行提交、相同時間戳與系統時鐘倒退、提交與截止競爭、成功組別亦不例外的學生隱私、斷線重連 snapshot，以及活頁簿完整語意保留匯出。

#### Scenario: 執行核心規則測試套件
- **WHEN** 完整測試套件執行
- **THEN** 每項核心規則至少有一個成功案例與相關錯誤或邊界案例

#### Scenario: 驗證不同版面學習單
- **WHEN** 匯入測試使用題數、列或欄位置不同的合成 `.xlsx` fixture
- **THEN** 測試確認系統依表頭及實際位置建立 mapping，而非依賴範例座標

### Requirement: 支援至少兩組學生並行 Demo
本機 Demo MUST 能同時開啟一個老師 session 及至少兩個互相隔離的學生瀏覽器 session，並完成相同題目及不同題目的並行提交、修改與截止驗收。

#### Scenario: 兩組同時提交相同題目
- **WHEN** 兩個學生 session 分別綁定不同組別並近乎同時提交同一題
- **THEN** 老師即時看到兩組答案，學生只看到本組資料，截止後結果具有穩定順位

#### Scenario: 兩組提交不同題目並修改
- **WHEN** 兩組分別作答不同題目，且其中一組修改既有答案
- **THEN** 各題獨立保存狀態，修改組使用新的有效提交時間

### Requirement: 提供人工驗收流程
專案 SHALL 提供繁體中文人工驗收清單，依序涵蓋匯入預覽、建立組別、開始、多人提交、修改、隱私、截止、結果及匯出，並列出每一步預期畫面與資料結果。

#### Scenario: 老師依清單完成 Demo
- **WHEN** 驗收者依人工清單操作老師及兩組學生畫面
- **THEN** 每個核心功能都有明確操作、預期結果及可供判定通過或失敗的檢查點

### Requirement: 測試資料不得包含機密或真實個資
納入版本控制的測試 fixture MUST 使用合成題目、組別與答案，並 MUST 不包含帳密、金鑰、真實學生資料或課堂上傳檔。執行期間產生的資料庫、上傳與匯出檔 MUST 位於 Git 忽略的 `var/` 或隔離暫存目錄；OpenSpec、程式碼、測試與 `tests/fixtures/` 合成資料 MUST 可納入版本控制。

#### Scenario: 檢查版本控制內容
- **WHEN** 開發者檢查待提交檔案與測試 fixture
- **THEN** 只包含合成資料，且不追蹤 `.env`、本機資料庫、真實上傳或匯出結果
